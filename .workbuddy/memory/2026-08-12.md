## 修复 FOREIGN KEY constraint failed（后端 SQLite）
- 报错：`database error: FOREIGN KEY constraint failed`（error.rs 的 `Database(#[from] rusqlite::Error)`）。
- 根因（重构引入的 FK 写入脆弱点）：`ON DELETE SET NULL` 只在被引用行**被删时**生效；INSERT 一个**不存在的非空 FK 值**仍会直接报 FK 失败。
- 触发场景：知识卡/伏笔的 `source_chapter_id` / `source_artifact_id` 在旧数据或迁移数据中可能为「指向已不存在行」的陈旧非空值；重构把知识卡接入检索索引（`apply_action_proposal` 对 knowledge_card 类型 `enqueue_project_search_job`），全量重索引会把这些陈旧值写进 `story_search_documents`/`story_search_sources`（二者对 chapter_id/source_artifact_id 均为 CASCADE FK）→ 整轮重索引崩溃。
- 修复（防御式 NULL 回退，仅在引用行确实存在时沿用，否则置 NULL）：
  - `src-tauri/src/v2_storage.rs`：`apply_proposal_tx` 的 `knowledge_card` / `foreshadowing` 分支写入 `source_chapter_id`/`planted_chapter_id` 前经 `existing_chapter_id(tx, ...)` 解析。
  - `src-tauri/src/story_search.rs`：新增 `existing_chapter_id`/`existing_artifact_id`，在 `refresh_knowledge_card`、`refresh_foreshadowing` 及全量重索引循环里对 `chapter_id`/`source_artifact_id` 做回退。
- 验证：`cargo test --lib` 165 passed / 0 failed（编译通过）。
