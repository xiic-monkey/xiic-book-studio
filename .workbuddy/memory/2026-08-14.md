## 设计决策：保留 SQLite 外键
- 用户质疑"为什么还用外键 / 外键是否该移除"。经讨论确认：本地单文件 SQLite（Tauri）无 scaling 成本，FK 免费且提供 `ON DELETE CASCADE` 级联清理，决定保留。
- 明确 FK 报错的处理原则：根因多为"写入陈旧 FK 引用"，修复用 NULL 回退（existing_*_id 辅助函数），而非关/删 FK。
- 已记入 MEMORY.md「数据完整性约定」节。

## 前端：章节试读/修订 UI 修正（BookStudioWorkspace.tsx）
- 发现 4 个 UX 问题并已修复：
  1. 试读页原本把审阅 JSON 原文和卡片重复渲染，且不显示被审正文 → 改为用 `parent_artifact_id` 经 `useArtifact` 拉取源产物正文并标注「被审原文 · vX」（注意：`detail.artifacts` 是 `ArtifactSummary` 无 `content`，需走 `useArtifact` 拿完整 `Artifact`）。
  2. `visibleArtifacts` 原本按 `stage === selectedStage` 分桶，草稿/修订被隔开无法同屏 diff → 章节体 stage 合并 `bodyStages`(["revision","draft"]) 展示，版本 tab 加 `stageLabel` 区分。
  3. 修订 tab 主按钮文案"生成候选"不准确 → 改为 stage 感知：`revision`→生成修订 / `draft`→生成草稿 / 否则生成候选。
  4. 试读产物不该有"人工通过"（批注成不了正文）→ 用 `selectedArtifact?.stage !== "review"` 守卫隐藏。
