# 阶段 Agent 与题材 Skill 解耦设计

日期：2026-11-22 · 状态：已实现

配套文档：[实现计划](../plans/2026-11-22-stage-agents-genre-skills-implementation.md)

## 1. 决策

**同一个工种用同一个 Agent；不同题材通过 Skill 区分。** 写作、试读、修订仍是不同的 Agent。悬疑、都市异能、仙侠等不是新的 Agent，而是同一工种在不同项目中加载的写作方法与判断标准。

| 方案 | 收益 | 代价与判断 |
|---|---|---|
| 阶段 Agent + 题材 Skill（采用） | 阶段职责、工具、产物和验证可复用；题材规则只维护一份 | 需要一个明确的 Skill 选择与注入入口；适合当前所有题材共用创作流程的情况 |
| 题材专属 Agent + 题材 Skill（改造前） | system prompt 有一段简短的题材定位 | 题材身份和 Skill 都在描述写法；两者一起生效，关掉 Skill 仍有同类规则残留 |
| 按题材各建一套 Agent | 可以独立规定读哪些数据、调用什么工具、产出什么 | 当前没有这种差异。规格与测试会随题材和阶段组合膨胀，还会出现模型设置、工具和契约不一致 |

拆新 Agent 的标准是**职责、输入边界、可用工具、输出或审批方式存在实质差异**，而不是规则多或想换个角色名。例如「只读读者已看到的信息，不读作者预设真相，并输出独立证据链报告」可以成为悬疑专项审计；当前的章节试读只是换检查重点，不需要拆 Agent。本期不实现专项审计。

## 2. 改造前的问题与改造范围

1. 旧模块 `genre_agent.rs` 中四个 `GenreAgentProfile` 的主 Skill key 和 Agent key 一一对应，辅助 Skill 许可也相同。`compose_stage_agent` 给已有 Agent 拼接题材身份，复用既有执行路径、模型配置、工具和产物。关闭 Skill 后，题材身份里的公平推理、资源代价等要求仍在。
2. [`workflow.rs`](../../../src-tauri/src/workflow.rs) 的 `build_chapter_task_contract` 绕开 Skill 内容，按题材硬编码进度增量。即使去掉身份，关闭 Skill 也仍会出现题材写法。两个来源应一起收敛。
3. 题材路由目前通过 `project_genre_agents` 中转，设置页把派生身份展示为「当前项目专属 Agent」。项目没有手动绑定入口；创建、更新和启动对齐均以项目题材为准。可以从 `Project.genre` 直接选择 Skill，无须增加新的绑定表。
4. 预览、正式运行、跨章审校不是同一个入口。部分路径的 system prompt 在预算裁剪前就声明 Skill 已加载；跨章审校缓存只区分章节输入，预览指纹也未包含 Skill 规则正文。切换或编辑 Skill 后，已有缓存可能掩盖改动。

**范围内：** 角色提示词、题材选择与规则注入、受影响的预览与审校缓存、设置页展示、前后端返回字段、相关测试。

**范围外：** 新增 Agent、改变模型或工具配置、增加题材或混合题材策略、修改正文采用和质量门禁、重写编排、迁移或清理 SQLite 数据、批量改写用户的 Prompt/Skill、承诺模型效果提升。

## 3. 职责与规则归属

| 层 | 负责 | 不负责 |
|---|---|---|
| 阶段 Agent | 接受任务，决定按哪种工作流程处理，按现有工具权限与输出契约交付 | 不内置任何题材的规则，不因项目题材换 Agent ID 或模型 |
| 共享工作协议 | 事实来源优先级、项目范围、未知保留、候选稿与采用边界、阶段职责 | 不放题材规则；不拿掉代码层的校验 |
| 题材 Skill | 读者期待、题材特有的叙事方法、各阶段关注点 | 不新增工具、字段或流程；不创造本书事实，不覆盖 Agent 契约 |
| Craft Skill | 可跨题材复用的方法，如角色知情、状态承接和主角主动性 | 不充当题材路由，不重复题材条款 |
| 项目数据 | 该书的正文、设定、角色、章节计划、作者指令与已校验资料 | 题材名和 Skill 示例不能补足书中缺失的证据或设定 |

例如，同一个试读 Agent 在悬疑项目检查关键线索是否早于揭晓，在仙侠项目检查升级是否有资源来源与代价。两者照常引用可核对的原文，走现有 `submit_review_issues` 工具与 `{summary, issues}` 契约。Skill 不能改严重度的合法值、放宽引文校验，或要求试读 Agent 亲自改稿。

Agent 系统提示词为「阶段模板 + 原有共享工作协议」（仅在原设计的五条组合职责使用），不再拼接题材人设或 Skill 注入声明。用户自定义 Agent Prompt 可能主动写入题材内容；系统不删除这些内容。「禁用题材 Skill」只关闭应用管理的题材规则，不承诺模型不理解题材标签，也不剥掉已有作品本身的题材信息。

### 3.1 选择与启停

- `detect_genre_skill` 是唯一的题材映射。保留现有顺序：修仙／玄幻／仙侠／升级／男频 → 悬疑／怪谈／推理 → 异能／超能／灵气复苏 → 通用连载。未知题材进通用；组合题材仍只选一个。不从 `project_genre_agents` 读绑定。
- 选中规则的数据库记录存在时，只使用用户当前启用的内容。关闭、内容空白或当前阶段没有可渲染的规则段时，不注入替代题材、不回退至通用方法。仅在选中 key 的记录**不存在**时用同 key 的内置文件兜底。
- `## Always` 跨阶段，`## Stage: <stage>` 仅适用当前阶段；允许已有自定义文本只写其中一段，不就地重排或覆盖。两段都取不到时不输出只有标题和来源的空壳。
- Craft 继续受阶段 Agent 保存的 `allowed_skill_keys`、规则启用状态及可渲染内容限制。为保持现有能力边界，本期仍只加载当前四种题材共同支持的 `continuity_and_agency`，不因去掉题材 profile 就激活过去未注入的其它辅助 Skill。题材开关与 Craft 开关相互独立。

### 3.2 运行入口矩阵

| 入口 | 应用管理的题材规则 | Craft | 备注 |
|---|---|---|---|
| 设定、阶段大纲、角色生成 | `Always` + `setting` / `outline` / `characters` | 按故事架构 Agent 许可 | 以实际任务阶段选段，不用 Agent key `story_architect` 当阶段 |
| 章节写作、试读、修订 | `Always` + `draft` / `review` / `revision` | 按执行 Agent 许可 | 预览、直接运行、委托运行和旧工作流路径同一规则；修订反馈入口同上 |
| 产物局部编辑（`artifact_revision`） | 沿用原入口 | 沿用原入口 | 使用选中片段及局部编辑指令，独立于章节修订 |
| 跨章连续性审校 | `Always` + `review` | 按连续性审校 Agent 许可 | 保留现有题材审校方法，不套写作 Agent 身份；规则改动必须使结果缓存失效 |
| 主 Agent 路由 | 不加载 | 不加载 | 仍可读项目题材标签；子 Agent 自行加载适用规则；不改变委托、依赖与取消 |
| 创作基准一致性审校 | 不加载 | 不加载 | 检查已采用资料能否自洽；沿用架构 Agent 的共享工作协议，不假定将注入 Skill |
| 索引、账本、搜索、提案提取等后台任务 | 不加载 | 不加载 | 已有阶段内生成的产物可以作为数据；不得给工具提取路径重新加载写法 |

### 3.3 章节任务与规则去重

通用章节任务卡保留本书目标、阻力、前章状态、章节模式、应发生的变化与结束条件。删除 Rust 的题材 `payoff` 分支及其提示行。逐条对照三个对应题材 Skill 的 `Stage: draft`：能表达原要求的规则保留原文，缺少的增量要求合并进去，不硬搬旧话术、不增加一个新的预算区块。悬疑是证据或判断发生变化；都市异能是能力边界、代价、身份或社会反馈发生变化；仙侠是按本章模式给出可见增长，允许获得资源、情报、筹码或付出代价，不强制升级。对于自定义 Skill，不自动追加这些默认规则。

如果内置 Skill 在指定字段、数量或内容边界上与对应阶段的当前契约冲突，只改 Skill 的表达。例如章节进展和代价可写入既有章节计划内容，不新增固定字段；设定阶段的创作范围受当前工具契约约束。此次不改阶段契约来迎合 Skill。

### 3.4 实际上下文与缓存

- 预览和正式请求由同一个运行时入口选择并渲染 Skill。预览保存准备阶段裁剪后的基础上下文；正式请求沿用该 Skill 快照与通过校验的 Agent 配置，不重新解析题材规则。现有执行时账本补充和最终预算仍可减少保留的规则，预览不保证与发给模型的最终请求逐字相同。带显式预览 ID 启动时检查项目、候选、Agent 配置和 Skill 输入是否过时；不带 ID 则以本次自动准备时取得的快照为准。
- 指纹必须包含本次注入入口、所选 key、实际渲染的题材和 Craft 规则。准备预览时，用**生成这一份 Prompt 的同一份** Skill 快照计算指纹，不在异步工具返回后重新读规则来给旧上下文盖新指纹。无关题材或当前阶段未读取的规则编辑不要求使该预览失效。
- 只在已走预算裁剪的入口保留现有 24,000 字符上限；跨章审校仍发送完整证据，不在本期新增裁剪。识别 Skill 段同时检查渲染标题与来源行，不因正文里出现英文 `Skill` 或同名标题就认作规则；这不是内容信任边界，用户文本即便逐字包含相同标记也仍按数据处理。先压缩其它低价值上下文，极端情况下才裁剪 Skill；只含阶段规则的 Skill 若丢掉唯一规则，整段移除并记录。system prompt 不再承诺有某个 Skill，因此整段移除后没有虚假声明；设置页的「启用」也不是对每次请求保留量的承诺。
- 跨章审校用实际渲染的项目、已采用资料和规则文本与原章节版本／文本一同生成缓存键，升级命名空间。缓存命中不重新运行账本工具。旧报告可以查看，不作为新请求的缓存。创作基准既有指纹、历史运行记录与已采用产物不重算。已经开始的执行不因临时改配置而中断。

## 4. 设置、契约与兼容

- **设置 → Agent：** 去掉「当前项目专属 Agent」卡片，只管理阶段 Agent 的名称、职责、Prompt、模型、工具与既有的辅助 Skill 许可。不引入题材选择器。
- **设置 → Skill：** 有当前项目时，用一行显示「项目题材 Skill」及选中的名称、启用状态；从工作区返回的 `genre_skill` 识别选中的 key，从最近保存的 Skill 列表读取状态，保存后原地更新。没有项目不显示此行。开关属于 Skill 库，作用仍是所有匹配该 Skill 的项目，不伪装成当前项目专用开关。
- `ProjectWorkspace` / `ProjectDetail` 同版把 `genre_agent` 替换成 `genre_skill: { skill_key, name, enabled }`。`enabled` 指库开关，不是「此次注入成功」；缺记录而使用内置兜底时为 `true`。桌面端、开发服务与仓库前端同时更新。Dev REST 返回字段有意变更；无仓库外调用方兼容承诺，如发布前确认有下游调用者，需要先协调升级，无须复活运行时的题材 Agent。
- 本次拆分沿用工作区已有的 SQLite schema 版本。保留 `project_genre_agents` 表和存量记录供旧版本回读，新运行时不读取或维护绑定。回退时前端与后端成对回退。旧版启动只补缺失绑定和特定历史 key，可能保留在新版改题材之前的绑定。使用已备份的数据库副本验证回退，并按[旧版回读](../../agent-design.md#旧版回读)处理失配记录。

## 5. 验收与质量验证

| 验收项 | 证据 |
|---|---|
| 共用 Agent | 两个不同题材的试读请求使用同一 Agent ID、模板、工具和模型，题材注入片段不同；没有第二个题材身份 |
| 开关真实 | 悬疑、仙侠、都市异能关闭后，实际请求没有该 Skill、旧身份和硬编码题材增量；Craft 和项目事实仍在 |
| 路由与隔离 | 同项目改题材，下一次运行换 Skill 不换 Agent；历史绑定、缺绑定和禁用不串到其它题材 |
| 多入口一致 | 六个阶段按 `Stage` 切片；主 Agent 和基准审校无题材规则；跨章审校使用 `review`；长上下文裁剪不会把正文判作 Skill |
| 缓存与兼容 | 编辑、启停适用 Skill 后旧预览必须重做，旧跨章报告不得命中；存量定制和 runs 仍可读，前端与生成契约一致 |

模型输出质量和结构解耦分开判定。历史 F7 复测结论为 `INCONCLUSIVE`，且没有隔离题材身份、硬编码增量和上下文供给等因素，不用作「合并一定不退化」或「Skill 无用」的依据。用悬疑和仙侠各一个写作与试读样本做新旧对照，固定模型与证据供给，分别看任务兑现、题材特有问题召回、误报和引文合法性；不能比较时只记录局限，不补造结论。可重复的契约或事实边界回归阻止发布；质量差异未定时明确标注，不宣称效果改善。
