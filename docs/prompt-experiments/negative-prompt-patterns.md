# 负向提示词实验清单

本文记录已经在 Xiic Book Studio 的真实小说工作流中产生负向结果的提示词或 Skill。它们不是推荐模板，也不应重新注册为默认 Agent 或常驻 Skill。

对应测试证据见 [2026-07-19 StoryForge 提示词 A/B 测试报告](../test-reports/2026-07-19-storyforge-prompt-ab.md)。

## 判负标准

满足任一条件即可判负：

- 漏掉原方案能够稳定发现的事实、连续性或状态问题。
- 增加无批准来源的人物、规则、能力、资源或既往事件。
- 把阶段大纲写成正文预演，提前消费后续冲突和谜底。
- 为遵守形式而牺牲召回、因果边界或人工可校准性。
- 只有单次表现改善，重复测试不能稳定复现。

## NEG-001：人物反应与叙事节奏常驻 Skill

### 来源与意图

- 来源：参考 StoryForge `P10-C` 的“场景结果 -> 人物反应 -> 下一决定”思路。
- 实现：作为 `reaction_and_pacing` Craft Skill 注入试读 Agent。
- 原意：避免重大事件发生后角色无反应，同时允许追逐、战斗等高压场景压缩或延迟反应。

### 实验提示词

```markdown
# Reaction And Pacing Skill

## Always
- 事件结果与下一行动之间不必固定插入反应段。先根据结果的不可逆程度、人物身体或关系是否改变、当前行动压力和人物性格，选择完整反应、压缩反应、延迟反应或直接续接行动。
- 反应可以通过身体、动作、语言、判断、回避、沉默或选择体现，不等于必须写内心独白，也不要求按固定步骤排列。
- 重大创伤、严重伤势、背叛、核心认知改写或关系决裂不能无理由立刻恢复。若当前节奏不适合展开，至少保留一个会影响后续行为的痕迹，并在合适位置兑现。
- 日常阻碍、重复信息和连续动作链可以压缩或跳过反应，避免每个场景机械地停下来总结感受。
- 有篇幅的反应必须改变人物的下一次判断、行动方式、关系姿态或风险选择。只重复“震惊、愤怒、沉默、下定决心”而没有后续影响，应压缩或删除。
- 多人物面对同一结果时，应依据各自已知信息、欲望、利益和风险产生不同外显反应，不要求轮流同步表态。

## Stage: outline
- 大纲阶段：只为真正改变人物状态或下一步选择的结果预留反应空间；普通过场不必单列反应节点。
- 大纲阶段：重大结果若安排延迟反应，标出它暂时被什么压力压住，以及最晚在哪个后续节点产生行为后果，避免永久遗忘。

## Stage: draft
- 正文阶段：结果发生后先判断人物还能不能、愿不愿、需不需要立刻处理。高压行动中可以先求生或办事，但伤势、恐惧、背叛和认知冲击应从动作、判断或语言中留下痕迹。
- 正文阶段：反应段应从本章已有事实和人物状态生长出来，不能为了显得深刻补充无来源的童年、秘密、动机或世界设定。
- 正文阶段：若人物的下一决定与此前计划相同，要写清新结果改变的是执行方式、风险判断、筹码或优先级；若什么都没改变，可压缩这次结果，避免伪变化。

## Stage: review
- 试读阶段：只有当事件实际改变了人物的身体、关系、目标、风险或核心认知，而后文完全没有行为、语言、判断或选择上的承接时，才标出“反应断层”。不能机械要求内心戏。
- 试读阶段：区分“有意延迟反应”和“作者忘记后果”。前者应有被压住的外显痕迹或后续兑现位置；两者都没有时再判问题。
- 试读阶段：检查反应是否改变下一决定的可信度。若人物经历重大结果后无理由恢复原状态，按影响标为 moderate 或 major，并引用结果与后续行动两处原文。
- 试读阶段：快节奏追逐、战斗、逃生和连续操作中，直接续接行动本身不是缺陷；除非伤势、信息或关系变化按已知规则本应改变行动能力。

## Stage: revision
- 修订阶段：用最小必要反应修复下一决定的可信度，优先补一个动作、判断、语言变化或选择代价，不为完整而添加泛化沉思。
- 修订阶段：若重大反应被延迟，在当前场景留下可追踪痕迹，并安排后续兑现；不要让角色当场长篇复盘而破坏正在进行的行动。
- 修订阶段：若反应只是重复情绪标签，删去重复部分，把保留内容落到行动方式、关系姿态或风险选择的变化上。
```

### 负向结果

- 基线试读报告 `116` 找到 5 条重要问题。
- 注入 Skill 后，报告 `117` 只留下 2 条；重复运行的报告 `118` 只留下 3 条。
- 两次实验均漏掉基线能够发现的硬问题，尤其是威胁断线、锁脉散状态承接和部分章节任务未兑现。
- 结论：Skill 本身并非错误写作知识，但作为常驻独立 Skill 会与事实边界、状态连续性和章节任务争夺模型注意力。

### 当前状态

- 源码注册已撤回。
- App 技能库记录 ID `365`，`enabled = false`。
- 禁止在没有分层调用或独立专项审校的情况下重新设为常驻 Skill。

## NEG-002：故事架构长约束补丁

### 来源与意图

- 来源：StoryForge 中“角色变化必须有触发事件”和“当前卷不得提前消费后续卷”的方法。
- 实现：追加到故事架构 Agent 的“细化当前阶段”模式和大纲任务约束。
- 原意：限制能力越界、角色知情越界和过度细化。

### 实验提示词增量

```text
每项能力、资源、规则和角色知情变化必须能指出已批准来源或本阶段内可见的获取/触发事件；没有来源的只能保留为待验证痕迹，不能成为解决冲突的现成答案。章节任务保持生产卡粒度：写清进入状态、目标、阻力、关键变化和退出条件，不预写完整战斗流程、对白或场景调度。规划必须停在当前阶段退出变化，不提前兑现下一阶段的核心冲突或谜底。
```

配套任务约束：

```text
不要把章节正文、完整战斗步骤、对白调度、重复规则或远期谜底提前写进大纲。已批准设定是能力合同：核心器物、血脉、功法和身份只能使用设定中已明确的功能；任何新效果只能作为未验证痕迹、外部一次性条件或远期问题，不能直接成为稳定解法。角色立场、知情范围、关系和能力若发生变化，生产卡必须写出本阶段内可见的触发或获取路径；若写不出来源，就保持未知或删掉该变化。
```

### 负向结果

- 产物 `124` 保住了第 1-5 章正式正文边界，但仍预写具体战斗过程。
- 无批准来源地新增周元济、方仲、丹阁规则和多项古炉机制。
- 黑牌和赤髓继续被扩展成解决冲突的现成能力，提示词中的“来源”被模型用新编事件自我满足。
- 结论：原则性禁令无法可靠约束故事架构输出，继续叠加只会增加上下文噪声。

### 当前状态

- 提示词增量已撤回。
- 产物 `124` 保持 `pending_human_approval`，未批准、未应用。

## NEG-003：六字段短生产卡

### 来源与意图

- 来源：StoryForge 章节大纲用短摘要限制细节的思路。
- 实现：每章只允许六个字段，每字段一句，不允许子列表。
- 原意：用输出结构代替长段禁令，减少完整战斗和场景预演。

### 实验提示词增量

```text
每个待写章节严格只写六项：章节模式、进入状态、章节目标、主要阻力、预期状态变化、退出条件。每项只写一句，不使用子列表；状态变化只写本章结束时可验证的结果，不展开逐招战斗、完整场景流程、对白或具体调度。结尾可以是结果落地、决定形成、信息改写、行动启动或情绪余韵，不强制每章制造危险式钩子。已批准设定和正式正文是能力与事实合同：具体人名、组织、物件、资源、规则、能力用途和角色知情范围必须能在其中找到来源。没有来源的新要素只能标为“待验证”，且不能承担本阶段获胜、脱困或升级的现成解法。不要把重复规则或远期谜底提前写进大纲。
```

### 负向结果

- 产物 `125` 表面遵守六字段格式，但从第 6 章一路规划到第 17 章，输出反而比 `124` 更长。
- 新增赤髓晶核、火种印记、苏清源、内门长老、炉基等未批准事实。
- 直接规划“火脉反噬被根治”“赤髓从此可以自生”等永久能力升级，提前消费远期谜底。
- 结论：格式收紧只减少段落形态，不会自动建立事实边界；模型会把越界内容塞进“状态变化”和“退出条件”。

### 当前状态

- 提示词增量已撤回。
- 产物 `125` 保持 `pending_human_approval`，未批准、未应用。

## 后续复测要求

这些方法只有在架构发生以下变化后才值得重新测试：

1. 将专项方法放入独立调用，不与主试读或主大纲提示词竞争注意力。
2. 输出先经过结构化事实校验，未批准实体和能力可以被程序识别并阻断。
3. 使用同一项目、同一候选稿、同一模型参数做至少一次基线和两次实验重复。
4. 预先定义不可退化指标；任何硬问题召回下降或事实越界增加都直接判负。
5. 实验产物始终保持待人工确认，不得进入正式正文或创作基准。
