# Xiic Book Studio 项目功能说明

> 本文按当前代码实现整理，用于说明 Xiic Book Studio 已具备的产品功能、典型使用方式和边界。它不是产品路线图；文中未列出的能力不应视为已实现。

## 1. 产品定位

Xiic Book Studio 是一个桌面端 AI 小说创作工作台。它把长篇小说创作拆分为“创作基准 → 章节写作 → 试读 → 修订 → 人工采纳”的可回溯流程，并将设定、角色、事件、物品、伏笔和正式章节正文沉淀为项目资料。

核心原则：

- AI 生成的是候选产物，不会自动成为正式内容。
- 设定、大纲、角色、章节草稿、试读报告和修订稿都保留为独立版本。
- 只有人工通过的草稿或修订稿才会成为章节的正式内容。
- 后续创作优先使用已批准资料、已通过正文及其衍生索引，以降低前后矛盾风险。

## 2. 核心创作流程

```text
新建书籍
  → 初始化/确认创作基准
  → 细化阶段大纲与角色
  → 新建章节并生成草稿
  → 试读检查
  → 修订或局部修改
  → 人工通过并应用为正式正文
  → 自动/手动更新资料索引，进入下一章
```

应用会对主要阶段设置前置条件：

| 阶段 | 作用 | 主要前置条件 |
| --- | --- | --- |
| 世界与规则 | 建立核心设定 | 无 |
| 阶段大纲 | 规划当前故事阶段 | 已通过设定 |
| 角色卡 | 设计主要角色 | 已通过设定和大纲 |
| 写作 | 生成单章正文草稿 | 已通过设定、大纲、角色，以及已确认的创作基准/一致性审校 |
| 试读 | 生成问题报告 | 已选择候选草稿/修订稿，或已有正式正文 |
| 修订 | 生成完整修订稿 | 通常需要已通过试读报告；也可基于指定候选版本修订 |

## 3. 功能说明

### 3.1 书籍与章节管理

- 新建、搜索、编辑和删除小说项目。
- 为项目维护题材、目标字数、故事前提和状态。
- 新建章节、快速创建下一章、重命名章节和删除章节。
- 删除章节时，其相关正文、草稿、试读、修订稿和运行记录会一并删除。
- 提供“正式内容”和“创作工作台”两种主视图：前者只展示已采纳正文，后者用于生成、检查和修改候选版本。

### 3.2 创作基准与故事架构

“创作基准”用于统一维护故事长期约束和阶段级规划。故事架构 Agent 支持：

- **初始化创作基准**：生成或补全项目的核心故事基准。
- **补充设定**：迭代世界规则、禁忌、题材风格和持续冲突来源。
- **细化当前阶段**：生成或更新当前阶段的目标、进入状态、冲突和退出变化。
- **扩展下一阶段**：在当前阶段之后规划后续阶段。
- **补充角色**：基于已批准设定与大纲生成角色卡。
- **一致性审校**：检查创作基准内部冲突，输出问题、影响和建议返工方向。
- **定向返工**：针对审校问题生成候选修复版本。

创作基准可由人工确认；在正文写作前，系统会检查当前基准是否已确认，以及相应的一致性审校是否可用。

### 3.3 设定资料、角色、物品、事件与伏笔

项目资料区包含以下内容：

- **设定资料**：可用卡片记录世界观、修行体系、地图与地点、势力与组织、禁忌与边界、重要物件等。资料卡可先保存为待人工确认，确认后启用，也可归档。
- **阶段大纲与角色卡**：查看并迭代故事架构 Agent 生成的对应产物。
- **物品与资源**：展示从已通过正式正文中抽取的实体与状态变化。
- **事件时间线**：展示有原文出处的事件，并可回到对应正式章节。
- **角色时间线**：按角色查看其在已索引章节中的状态变化与相关事件。
- **伏笔账本**：登记伏笔内容、埋设章节、预期回收章节或回收里程碑；支持“待确认 → 追踪中 → 可回收 → 已回收”的状态管理。

对于可从候选文本中识别出的资料变更，应用可以生成“待采纳资料变更”。用户可编辑候选内容，再选择采纳或拒绝；采纳后才会真正写入资料卡或伏笔账本。

### 3.4 章节写作、试读与修订

每个章节可在创作工作台中经过以下流程：

1. **写作**：AI 根据已批准资料、当前章节、历史上下文和人工指令生成完整正文草稿。
2. **试读**：AI 输出结构化问题清单，重点覆盖章节任务兑现、事实边界、叙事问题与前后连续性。
3. **修订**：AI 结合原稿、已批准试读意见、本地质量信号和人工反馈，生成完整修订稿。
4. **人工通过**：将选定草稿或修订稿应用为该章节的当前正式正文。

辅助操作包括：

- 带人工指令的局部迭代，尽量保留当前版本中未要求变动的部分。
- 整版重写，忽略当前候选版本重新生成。
- 基于试读意见请求修订。
- 对唯一原文片段进行手动替换，生成新的版本。
- 对指定原文片段提出 AI 局部修订要求，生成新的版本。
- 比较不同版本的差异。
- 清理章节历史版本；会保留正式正文和当前选中的版本。

### 3.5 质量、门禁与连续性检查

创作工作台提供多层检查工具，结果用于辅助判断，不替代人工决定：

- **质量检查**：分析单个产物的质量信号与评分。
- **通过前检查（章节门禁）**：针对当前章节草稿或修订稿，检查是否存在应在通过前处理的问题。
- **章节重规划**：为篇幅或章节任务不合理的候选稿生成拆章/重规划建议，并可将建议写入修订要求。
- **连续性审校**：检查已通过章节与候选稿之间的人物、物件、事件、知情范围、状态和承诺是否冲突。
- **状态账本核对**：针对候选草稿或修订稿，核对其叙述与已沉淀状态账本是否一致。

### 3.6 本地历史检索与资料索引

应用会从已通过的正式正文中构建项目资料索引，用于展示角色、物品和事件时间线，并辅助后续生成与审校。

- 支持查看每章资料索引状态，必要时手动重建。
- 支持本地混合检索：关键词/全文检索与向量检索结合，底层使用 bge-small-zh-v1.5、FTS5 trigram 和 sqlite-vec。
- 可按查询词搜索旧人物、物件、线索或事件。
- 可对初步召回结果进行 AI 相关性筛选。
- 可预览某次 Agent 调用将使用的上下文片段、字符数和估算 token 数；该预览只读，不修改项目数据。

### 3.7 仿写参考资料

- 支持导入单个 `.txt` 文本作为仿写参考，单文件上限为 20 MiB。
- 参考资料可启用/停用，并按“风格”“结构”标签选择参与当前调用的范围。
- 当前界面提示该参考仅在本次应用运行期间保存；启用的内容会发送给当前配置的 AI 服务。
- 移除参考只移除应用内临时资料，不会删除原始文件。

### 3.8 AI 服务、Agent 与写作技能配置

设置页面提供：

- 配置 OpenAI-compatible AI 服务地址、模型、温度和思考开关。
- 保存多个供应商配置，测试连接，并从供应商接口读取可用模型。
- 按 Agent 配置实际使用的供应商、模型和思考开关。每本书绑定题材专属 Agent；故事架构、写作、试读和修订是其不同工作模式。
- 查看 Agent 系统提示词。
- 管理写作技能库：修改技能名称、说明、启用状态和 Markdown 规则内容。
- 查看并重建当前项目的本地检索索引。

API Key 不会作为普通设置字段回显；当前版本会按供应商地址将其保存在本地 SQLite。macOS Keychain 仅用于迁移旧版本遗留的凭据条目。

### 3.9 版本、协作记录与导出

- 每次 Agent 生成会形成带阶段、版本号、父版本关系和状态的产物记录。
- 项目保留人工指令、修订要求、人工确认和 Agent 结果等协作记录。
- 保留运行记录，例如运行状态、耗时、输入与输出。
- 支持将项目导出为 **Markdown**；当前第一版只提供 Markdown 导出。

## 4. 推荐使用方式

1. 在“设置”中配置并测试 AI 服务。
2. 新建书籍，填写题材、目标字数和故事前提。
3. 进入“书籍资料”，初始化创作基准；核对后人工确认。
4. 生成并确认设定、阶段大纲和角色资料；必要时执行一致性审校并定向返工。
5. 新建章节，在“写作”阶段输入明确的人工作业要求并生成草稿。
6. 使用“试读”“质量检查”“连续性审校”和“状态账本核对”检查候选稿。
7. 结合问题报告请求修订，或使用局部替换/AI 局部修订处理局部问题。
8. 人工确认合格后，点击“通过并应用正文”。此时该版本成为正式正文，并可参与后续索引和检索。
9. 继续下一章；按需要维护伏笔、资料卡和故事阶段。
10. 项目完成或需要备份时，导出 Markdown。

## 5. 重要边界与注意事项

- AI 输出、质量检查和连续性审校都是辅助工具，**不能代替人工校对和最终创作判断**。
- 未经人工通过的草稿、试读报告、修订稿和故事架构产物不应当作正式事实。
- 将参考资料启用到 AI 调用时，相关文本会被发送至所配置的第三方 AI 服务；请避免导入无权外发的内容。
- 本地检索依赖本地模型资源和索引状态。正式正文更新后可能出现“待重建”状态，可在设置中手动重建。
- 删除书籍不可恢复，会删除其章节、产物和记录；删除章节也会级联删除章节相关内容。
- 当前导出格式仅支持 Markdown；编辑器外观偏好等部分设置仍标注为后续版本能力。
