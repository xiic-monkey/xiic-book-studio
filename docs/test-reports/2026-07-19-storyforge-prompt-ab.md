## 结论摘要

本轮保留了此前验证为正向的两项结构改动：

- 故事架构 Agent 把已通过正式正文视为不可回写事实，只从第一章未完成章节继续规划。

## 评价方法

### 试读实验

主要比较问题召回，不比较措辞风格。基线能稳定发现的 major/moderate 硬问题不允许丢失，重点包括：

- 事实越界。
- 角色、伤势、药物和物件状态断点。
- 上一章已建立的威胁是否断线。
- 章节任务是否真正兑现。
- 探索收益是否落地。

### 大纲实验

主要比较以下边界：

- 不重写第 1-5 章正式正文。
- 从第 6 章开始生成待写规划。
- 不扩展未批准能力、人物、规则和组织。
- 保持生产卡粒度，不预写完整战斗和场景流程。
- 不提前消费更远阶段的冲突和谜底。

## 最终决策

| 改动 | 决策 | 原因 |
| --- | --- | --- |
| 正式正文进度上下文 | 保留 | 能阻止重写第 1-5 章，并从第 6 章继续。 |
| 读者期待/推进证据/局部回报 | 保留 | 提供阶段级可验证目标，不强制固定节奏。 |
| `reaction_and_pacing` 常驻 Skill | 撤回 | 硬问题召回下降。 |
| 能力来源与触发事件长约束 | 撤回 | 无法阻止模型自编来源，增加提示噪声。 |
| 六字段短生产卡 | 撤回 | 只收紧格式，规划范围和事实越界更严重。 |
| 默认沿用最新未批准大纲 | 修复 | 现在默认使用已批准版本；只有人工显式选择候选稿才基于候选继续。 |

## 后续建议

下一步不应继续增加同层级提示词。更值得测试的是程序化事实门禁：让故事架构输出显式声明使用了哪些已批准实体和能力，后端再对不存在的引用进行阻断或要求人工确认。该方案仍需按同一基线、两次重复实验验证，不能直接进入生产默认值。
